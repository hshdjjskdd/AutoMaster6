# AUTO MASTER

Telegram-бот: реалистичный симулятор автомастерской.

**Статус: этап 6** (динамические заказы раз в 2 часа, сложность 🟢🟡🔴, несколько неисправностей, финансовая сводка; до этого — автопарк с редкостью, диагностика, магазин, склад, ремонт, сдача заказа). Этап 2: — к регистрации, меню и профилю (этап 1) добавлено постоянное хранение данных:
автомобили, заказы, неисправности и диагностика, склад и оборудование, история ремонтов, финансы.
Слой данных и игровая логика готовы и покрыты тестами, но игровые команды в Telegram (ремонт, склад, заказы)
пока не подключены к боту — это следующий этап.

## Что умеет бот

- `/start` — регистрирует игрока (при повторном вызове — приветствует снова) и открывает главное меню
- `/menu` — главное меню
- `/profile` или кнопка «👤 Профиль» — профиль игрока
- `/help` или кнопка «❓ Помощь» — справка
- на неизвестные команды и сообщения отвечает подсказкой, на внутренние ошибки — вежливым сообщением (подробности пишутся в лог)

Стартовые параметры нового игрока: **15 000 ₽**, **уровень 1**, **репутация 50/100**.

Бот работает только в личных сообщениях; в группах он молчит.

## Игровое ядро (этап 5)

Полный цикл: заказ → симптомы → диагностика → заключение → покупка деталей → ремонт →
проверка результата (тест-драйв) → сдача заказа.

- **Автопарк**: 96 моделей, свыше 220 комплектаций (`app/game_data/fleet.py`, `engines.py`).
  Заказы генерируются из 50 моделей с редкостью 🟢60% / 🔵25% / 🟣12% / 🟡3% и сложностью 1–5
  на каждую модель (`rarity.py`); игроку показывается только эмодзи.
- **Неисправности**: 36 причин с условиями применимости по тегам машины (`fault_catalog.py`),
  справочник симптомов/проверок/операций (`repair_catalog.py`), 20 проверок диагностики.
- **Запчасти**: единый каталог (`part_catalog.py`) — 40 типов, 3 качества (бюджетный / аналог /
  оригинал), совместимость по двигателю, кузову/шасси, свечам, АКБ, коробке. Записи в `parts`
  создаются лениво, миграция не нужна.
- **Магазин и склад**: кнопки «🛒 Магазин», «📦 Склад», `/shop`, `/stock`; покупка атомарна,
  защита от двойного нажатия (ключ идемпотентности с номером последней записи журнала).
- **Ремонт**: «🛠 Ремонт» в карточке заказа; операция выполняется ровно один раз
  (`repair_operations`, уникальность `(order_id, op_code)`), детали списываются только при успехе.
- **БД**: схема версии 5 — новая таблица `repair_operations`, существующие данные не меняются.

## Клиентские заказы (этап 3)

- «📋 Заказы» (`/orders`) — доска из 3 предложений: клиент, автомобиль (марка, модель, комплектация,
  двигатель, пробег), жалоба, симптомы, оплата и премия за срок (+15%). Предложения живут 12 часов.
- «Принять» создаёт автомобиль и заказ (статус «Принят») — машина встаёт в мастерскую. Мест в мастерской
  `1 + уровень // 3`. «Отказаться» бесплатно.
- «🏭 Мастерская» (`/workshop`) — активные заказы и их статус.
- Отмена: «Принят» — бесплатно; диагностика/ожидание деталей/ремонт — репутация −5; «Готов к выдаче» и
  закрытые заказы отменить нельзя.
- Автопарк: ВАЗ-2114, LADA Granta, Toyota Corolla, Volkswagen Polo, Hyundai Solaris — 3–4 комплектации
  каждой (двигатель, мощность, коробка, годы) в `app/game_data/fleet.py`; жалобы — в `scenarios.py`.
- Данные игроков изолированы: все запросы фильтруются по `player_id`. Схема БД — версия 3
  (таблица `client_offers`, создаётся автоматически).

## Диагностика (этап 4)

В карточке заказа в «🏭 Мастерская» — кнопка «🔧 Диагностика» (первая проверка переводит заказ из «Принят» в «Диагностику»).

- **12 проверок:** осмотр, напряжение АКБ, зарядка генератора, предохранители и цепи, стартер, свечи и катушки,
  ошибки OBD-II (+ живые данные), давление топлива, подсос воздуха, система охлаждения, тормоза, подвеска.
- **Реализм:** реальная поломка (1–2 причины) определяется один раз, хранится в БД и не показывается. Одна жалоба
  имеет несколько возможных причин; проверки дают разную и пересекающуюся информацию; значения зависят от модели
  и двигателя; у каждого замера шум; коды OBD-II бывают чужими, пропадают и не называют деталь; осмотр видит не всё.
- **Цена:** каждая проверка тратит игровое время (срок заказа сокращается в 2 раза быстрее) и деньги.
  Инструмент есть (покупается в «🧰 Инструменты») — платишь только расходники, нет — аренда.
  Оплата идёт в финансовый журнал категорией `adjustment` (новую категорию не вводили: у существующих баз
  CHECK на категории нельзя изменить без миграции).
- **Журнал:** таблица `diagnostic_check_runs` хранит все измеренные значения; «📒 Журнал» показывает записи.
- **Заключение:** игрок выбирает до 3 причин, они записываются как неисправности заказа (`faults`); после этого
  проверки закрыты. Верность вывода оценит этап ремонта.
- Защита: двойное нажатие кнопки не списывает деньги дважды, при нехватке денег ничего не сохраняется.

## Требования

- Python 3.12 или новее
- Токен бота от [@BotFather](https://t.me/BotFather)

## Установка и запуск

### 1. Получите токен

В Telegram откройте [@BotFather](https://t.me/BotFather), отправьте `/newbot`, задайте имя и username бота. BotFather пришлёт токен вида `123456789:AAH...`.

### 2. Установите зависимости

Linux / macOS:

```bash
cd auto_master
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Windows (PowerShell):

```powershell
cd auto_master
py -3.12 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### 3. Настройте окружение

```bash
cp .env.example .env        # Windows: copy .env.example .env
```

Откройте `.env` и впишите токен:

```
BOT_TOKEN=123456789:AAH...
```

Файл `.env` содержит секрет и не должен попадать в git (он уже в `.gitignore`). Токен нигде не хранится в исходном коде.

### 4. Запустите

```bash
python main.py
```

В логе появится строка `бот @ваш_бот запущен`. Откройте бота в Telegram и отправьте `/start`. Остановка — `Ctrl+C`.

## База данных

SQLite-файл `data/auto_master.db` создаётся автоматически при первом запуске, данные сохраняются между перезапусками.

### Инициализация

При каждом старте `init_db` безопасно делает следующее:

1. проверяет версию схемы (`PRAGMA user_version`, сейчас **2**); база более новой версии не открывается, выдаётся понятная ошибка;
2. создаёт недостающие таблицы — база этапа 1 дополняется новыми таблицами без потери данных игроков;
3. создаёт триггеры, запрещающие отрицательный баланс на уровне самой БД;
4. загружает каталог (запчасти, оборудование, конфигурации автомобилей). Повторная загрузка ничего не дублирует и не перезаписывает ручные правки цен.

### Таблицы

| Таблица | Назначение |
|---|---|
| `players` | игрок и его характеристики: деньги, уровень, опыт, репутация |
| `car_configurations` | справочник технических конфигураций (двигатель, трансмиссия, привод) |
| `cars` | автомобили игрока |
| `orders` | заказы и текущий статус ремонта |
| `faults`, `diagnostic_results` | неисправности заказа и результаты диагностики |
| `parts`, `stock_items`, `order_parts` | каталог запчастей, склад игрока, детали, установленные на заказ |
| `equipment`, `player_equipment` | каталог оборудования и оборудование игрока |
| `repair_history` | итог каждого сданного заказа (одна запись на заказ) |
| `financial_transactions` | журнал всех денежных операций |
| `client_offers` | заказы на доске (сложность, смета, скрытый план неисправностей) |
| `order_board_state` | у каждого игрока: время следующего обновления доски и серия пустых обновлений |

### Гарантии целостности

- **Деньги** меняются одним условным `UPDATE … WHERE money + δ >= 0`: баланс не уходит в минус даже при одновременных запросах. Каждая операция пишется в журнал с остатком после неё.
- **Детали на складе** списываются условным `UPDATE … WHERE quantity >= n`.
- **Статус заказа** меняется по схеме «проверить и заменить»: при двух одновременных запросах побеждает один. Допустимы только переходы, описанные в `game_data/order_flow.py`. Статус «завершён» выставляется только операцией `complete_order`.
- **Награда за заказ не начисляется дважды.** Три независимые защиты: условный переход `готов → завершён`, отметка `reward_paid_at` в самом заказе и уникальный ключ журнала `order_reward:<id>`. Повторный вызов возвращает `already_completed=True` и ничего не меняет.
- **Любая операция выполняется одной транзакцией**: деньги, склад и статус применяются вместе или не применяются вовсе.
- Внешние ключи включены; удаление игрока каскадно удаляет его данные, машину с заказами и запчасть, лежащую на складе, удалить нельзя.

### Изменение структуры

`create_all` **не изменяет уже существующие таблицы**. При правке моделей увеличьте `SCHEMA_VERSION` в `app/database.py` и подготовьте миграцию (в проекте пока нет Alembic). Пока на сервере нет данных, которые жалко терять, можно просто удалить `data/auto_master.db`.

### Резервная копия

Файл БД работает в режиме WAL, поэтому копировать его надо средствами SQLite, а не обычным `cp` на работающем боте:

```bash
python -c "import sqlite3; s = sqlite3.connect('data/auto_master.db'); d = sqlite3.connect('backup.db'); s.backup(d)"
```

## Динамические заказы и экономика (этап 6)

* Доска вмещает до 10 заказов. Раз в 2 часа реального времени (время хранится в БД, `order_board_state`) каждая сложность появляется независимо: 🟢 70%, 🟡 40%, 🔴 15%. После пустых обновлений вероятности растут (`PITY_STEP`), после 4 пустых подряд выдаётся лёгкий заказ.
* 🟢 — 1 неисправность, 🟡 — 2–3, 🔴 — 4–6 (не больше, чем поддерживает машина). Причины не повторяются, не противоречат друг другу и имеют совместимые детали. Клиент жалуется только на симптомы; причины выясняются диагностикой.
* Оплата = (выезд + работа) × коэффициенты машины + смета деталей × наценка; наценка ниже у сложных заказов, поэтому они не гарантированно выгоднее.
* При обновлении бот присылает сообщение; фоновая проверка идёт раз в 30 с, а при открытии доски просроченное обновление выполняется само.
* `/finance` или «📊 Финансы»: 💰 выручка, 🔧 расходы (детали, списанные на заказы), 📈 чистая прибыль.
* Все числа — в `app/game_data/economy.py`. Симуляция баланса: `app/game_data/economy_sim.py`.

## Запуск 24/7

Бот работает, пока запущен процесс. Для постоянной работы разместите его на сервере (VPS) или хостинге, который умеет держать долгоживущий процесс. Нужен **постоянный диск**: база SQLite хранится в `data/`, и если диск временный, игроки потеряют прогресс при каждом перезапуске. Одновременно должен работать только один экземпляр бота.

### Docker

```bash
cp .env.example .env            # впишите BOT_TOKEN
docker compose up -d --build
docker compose logs -f
```

База лежит на именованном томе `auto_master_data` и переживает пересборку и обновление. Обновление версии: замените файлы проекта и снова выполните `docker compose up -d --build`. Без compose: `docker build -t auto-master .`, затем `docker run -d --init --restart unless-stopped -e BOT_TOKEN=... -v auto_master_data:/app/data auto-master`.

### Запуск на VPS через systemd

```bash
sudo useradd --system --home /opt/auto_master automaster
sudo mkdir -p /opt/auto_master && sudo cp -r . /opt/auto_master && cd /opt/auto_master
sudo python3 -m venv .venv && sudo .venv/bin/pip install -r requirements.txt
sudo cp .env.example .env       # впишите BOT_TOKEN: sudo nano .env
sudo mkdir -p data
sudo chown -R automaster:automaster /opt/auto_master && sudo chmod 600 .env
sudo cp deploy/auto-master.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now auto-master
journalctl -u auto-master -f    # логи
```

Папка `data` должна существовать до первого запуска юнита, иначе systemd не сможет подготовить защищённое окружение.

## Проверка работоспособности

1. `python main.py` без `.env` — понятная ошибка про `BOT_TOKEN`, код выхода 1.
2. С неверным токеном — сообщение «Telegram отклонил BOT_TOKEN», код выхода 1.
3. `/start` у нового пользователя — приветствие и параметры: 15 000 ₽, уровень 1, репутация 50/100.
4. Повторный `/start` — «С возвращением», деньги не сбрасываются.
5. Кнопка «👤 Профиль» и `/profile` — карточка профиля.
6. `/menu`, `/help`, кнопка «❓ Помощь» — работают.
7. `/abracadabra` — «Неизвестная команда», обычный текст — подсказка.
8. После перезапуска бота профиль сохраняется.

## Частые проблемы

- **`Telegram отклонил BOT_TOKEN`** — токен скопирован неверно или отозван в BotFather.
- **`Не удалось связаться с Telegram`** — нет доступа к `api.telegram.org` (сеть, файрвол, прокси).
- **`TelegramConflictError` в логе** — бот уже запущен в другом месте (на другом компьютере или в другом терминале). Одновременно допустим только один экземпляр.
